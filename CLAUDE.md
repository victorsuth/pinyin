# 拼音大冒险（Pinyin Adventure）

A Duolingo-style pinyin practice game for a 2nd-grade child in mainland China who
still mixes up parts of Hanyu Pinyin. `index.html` (HTML + CSS + JS, no build,
no dependencies) plus pre-recorded audio in `audio/`; works offline by
double-click as long as the `audio/` folder sits next to it (without it, the
page falls back to the browser's speech synthesis).

The user (Victor, parent, IT admin) communicates in Chinese — reply in Chinese.
All UI copy is Simplified Chinese, written for a ~7-year-old.

## Deployment
- Hosted on **Netlify** (static, publish dir `/`, no build command).
- Plan: GitHub repo → Netlify auto-deploy on push to `main`. Repo was just
  created by the user; ask for `owner/repo` if not already set as the remote.
- Keep the file named `index.html` at the repo root. `netlify.toml` sets long
  cache headers for `audio/*/*.mp3` and no-cache for `audio/manifest.js`.
- Progress is stored in `localStorage` (keys prefixed `pyadv_`), so it is
  per-browser and tied to the site URL — don't change the domain casually, and
  never rename/remove existing storage keys (the child would lose progress).

## How the game works
- 9 categories (`ORDER`) + 听音连连看 + 混合挑战 + 错题本复习 + 综合考试:
  `nasal` 前后鼻音, `pingqiao` 平舌翘舌, `shape` 形近字母 (b/d/p/q, m/n, f/t),
  `tone` 声调, `tdrill` 声调专练, `spell` 拼一拼, `umlaut` ü 的规则,
  `whole` 整体认读, `triple` 三拼音节. 混合挑战 takes up to 3 per category,
  then shuffles (so the derived all-character categories don't dominate).
- **拼一拼** (`spell`, `makeSpellQ()`, `pickTile()`): items are every bank
  character once (`ITEMS.spell`, like tdrill). `splitPy()` splits the syllable
  into 声母 (`INITIALS`, y/w count as initials) + 韵母 with the tone number
  (medial goes with the final: g + uang1). 4 initial tiles (`CONF_INI`
  look-alikes / flat-vs-retroflex) and 4 final tiles (`CONF_FIN` confusable
  final, other tones of the same final, and `v…` after j q x y to drill the
  去两点 rule). Picking both auto-checks via `answer()` with a fake button; in
  the exam it only sets `L.pick`. Tapping a slot clears it.
- **听音连连看** (`mode==='letters'`, not in ORDER, home card next to 混合挑战;
  `startLetters()`/`letterRound()`/`pickLetter()`): 3 rounds × 4 pairs; left
  column speaker buttons, right column letters; tap speaker (plays the letter's
  呼读音) then the letter; correct pairs get an SVG line. Rounds are drawn
  from `LETTER_GROUPS` (confusable sets), weighted by the new storage key
  `letterHist` (wrong count per letter, only grows). `LETTERS` = 23 声母 +
  24 韵母 with the char/pinyin used to synthesize each sound (`letter|x` audio
  keys). All 声母 are read in the first tone as taught in class (the parent
  rejected fó/dé/tè/nè/lè/rì); er is ēr too (parent rejected ér). Letter
  audio keys are `letter|字母|合成字|拼音`, so changing a reading gives a new
  URL (the mp3s are cached as immutable). Synthesis quirks: o uses 哦 (喔 had
  a hump); l uses 乐 pinned to le1 (勒 was read lēi); ai uses 埃 (哀 sounded
  like 欸; the kept clip was picked by the parent — ASR hears it as English
  "I", so a regenerate would wrongly reject it); ang read alone came out as
  「洋洋」 or wasn't recognisable, so its clip is the first syllable cut from
  「肮脏」 (key uses 昂). ai/er/ang are in `HAND_PICKED` in gen_audio.py and
  are never regenerated by `--recheck-tones`. ü read alone comes out
  sounding like i — see below. Stars via `finish()` like a lesson
  (`prog.letters`).
- **声调专练** (`tdrill`, wide yellow card): the child is weak at tones. Its
  items are every bank character once (`ITEMS.tdrill`, built after the other
  categories, `cat:'tdrill'` so mistakes/review stay tone questions). Types
  via `makeToneQ()`: `tlisten` 听音辨调 (audio only), `tmark` 看字认调 (options
  always ordered 一二三四声 with `TONE_NAME` labels), `tplace` 标调位置 (tone
  mark placed on each vowel of the toneless syllable; falls back to `tmark`
  for single-vowel syllables). Wrong answers in `tone`/`tdrill` show a
  声调小课堂 row: mā má mǎ mà demo clips (`TONE_DEMO`, `say|妈/麻/马/骂`,
  pinned to ma1–4; 麻/骂 are out of the reading list but only heard, never
  shown).
- Item format in `CATS[id].items`: `[汉字, 词语, 数字标调拼音, [易混干扰项]]`,
  e.g. `['山','山羊','shan1',['shang1','san1']]`. `v` = ü. `py()` converts
  `shan1` → `shān` using standard tone-mark placement rules.
- **Word scope:** every 汉字 and 词语 in the bank is within the 统编版
  一年级上/下 + 二年级上册 识字表 (300+400+450 chars; the child is in 二年级上,
  unit 8 as of 2026-11). Verified page-by-page against the textbook PDFs the
  user supplied (lx-public.oss-cn-beijing.aliyuncs.com …/小学语文课本/语文X年级X册.pdf;
  the PDF text layer drops some glyphs, so render the 识字表 pages and check
  visually). Removed as out of scope: 棒 寻 菜 杯 麻 骂 糖 亿 需 驴 户.
  Re-check any new character before adding it.
  **Pinyin and words are also verified against the textbooks** (2026-11):
  every item's pinyin equals the 识字表 annotation (extracted with
  `pdftotext -bbox` on the 识字表 pages — 1a pp.120–122, 1b 123–125,
  2a 116–119 — matching each pinyin word to the char below it; the pinyin
  font stores tone vowels as capitals: QWAS=āáǎà ERDF=ēéěè TYGH=ōóǒò
  UIJK=īíǐì OPLM=ūúǔù VC=ǚǜ), and every 词语 occurs in the books' body text
  (`pdftotext -raw`). **Polyphone rule (user's):** avoid characters whose
  other common reading the textbooks haven't taught; use a single-reading
  character with the same pinyin instead (e.g. shou → 手, shu → 书). Removed
  for this: 熟 (shóu), 肚 (dǔ); kept because the other reading is rare or
  taught: 大 说 叶 家 绿 刷 (rare alt), 地 发 (both readings taught).
- `EMO` maps 汉字 → emoji picture hint. Characters without an emoji are only
  used in 看字选拼音 questions in hint mode. **The emoji is shown above the
  词语, so it must depict the whole word, not just the character** (the parent
  caught ⛰️ shown with 山羊). When changing a word, re-check its emoji; if no
  emoji fits, drop it (根 半 十 北 是 have none for this reason).
- Question types: `c2p` 看字选拼音, `listen` 听音选拼音 (disabled if no zh voice),
  `p2c` 看拼音选字 (in hint mode becomes 看拼音选图).
- 10 questions per lesson; wrong answers are re-queued at the end and added to
  the 错题本; stars by first-try accuracy (≥90% ★★★, ≥70% ★★).
- 综合考试 (`mode==='exam'`, `buildExam()`): 20 questions, no per-question
  feedback — child selects (can change) then taps 下一题/交卷; result page shows
  score /100, per-category bars and the wrong list. Selection: up to 14 items
  weighted by `3*mistakes + wrongHist` (current 错题本 first, then items ever
  missed), then ≥1 item per category, then remaining slots weighted toward
  categories with more mistakes / fewer stars. One question per 汉字.
  Wrong answers go into the 错题本; correct ones don't remove anything.
- If an item's 汉字 is replaced, its old `cat|字` keys stay in `mistakes` /
  `wrongHist` (never delete progress); `mistakeKeys()` skips keys without a
  matching item, and `buildExam()` only iterates `ALL`.
- Storage keys: `prog`, `letterHist`, `mistakes` (current 错题本, decremented by review),
  `wrongHist` (lifetime wrong count per `cat|字`, only grows — feeds the exam),
  `exams` (last 30 results: date, score, n, wrong keys), `xp`, `streak`,
  `today`, `speed`, `hint`.
- Praise voice: correct answers speak the on-screen praise (+ combo ≥3) via
  `cheer()` (rate ≥.85, pitch 1.25) before the item reading; lesson/exam
  result pages speak their message (exam: score first). Wrong answers just
  read the item. `speak()` accepts strings or `{t,rate,pitch}` parts.
- **Pre-recorded audio** (MiniMax TTS, voice `lovely_girl` 萌萌女童, model
  speech-2.8-hd): `audio/<voice-dir>/<hash>.mp3` + `audio/manifest.js`
  (`window.AUDIO_CLIPS={dir:[hash…]}`), generated by `tools/gen_audio.py`.
  Hash = FNV-1a (base36) of a key: `item|字|拼音|词` (one clip reads
  "字。词。词的字。" with pauses) or `say|文本` (praise, `连对N题！` N=3–30,
  LESSON_MSG, EXAM_MSG, GOAL_MSG, `N分！` N=0–100). `fnv()`/`clipKey()` in
  index.html must stay identical to the script's. `speak()` plays clips when
  *every* segment has one (single `<audio>` element chained via `ended`, first
  `play()` inside the tap), otherwise falls back to Web Speech. Item clips play
  at `SPEEDS[i].play` (.85/1/1.2), praise at 1. `preload()` warms the HTTP cache
  for the current + next item and the praise clips.
  **After adding/changing items or any spoken text, run
  `python3 tools/gen_audio.py`** (only generates missing files; needs
  `api.minimax.cn` allowed + the key as a Network secret or `MINIMAX_API_KEY`;
  M Plan subscription key works; RPM limit → script uses 2 threads + backoff).
  Every item's reading is pinned via `pronunciation_dict` (except ü syllables —
  the API's ü spelling is undocumented). **Tone QA:** isolated syllables from
  the TTS often come out with the wrong contour (the parent heard 一声 sound
  neutral and 二/三声 indistinguishable). `tools/tones.py` measures the F0
  contour of the first syllable (item clips) / last syllable (tone demos) with
  praat-parselmouth and checks it (一声 high-flat, 二声 rising from low, 三声
  dip-then-rise with a low minimum, 四声 high falling); `gen_audio.py` retries
  other punctuation/emotion/speed variants (`ITEM_TRIES`, `DEMO_TRIES`) until
  it passes, else keeps the closest. **Syllable QA:** with pypinyin installed
  it also runs MiniMax ASR (`/v1/speech_to_text`, model `asr-1.0`) on item and
  letter clips and rejects variants whose first recognised character can't be
  read as the expected syllable (caught ü→yī, lē→lēi). Caveat: ASR hears an
  isolated ü as i even in clips that are fine in context, so ü clips need the
  parent's ear. Run it with a Python that has
  `praat-parselmouth numpy` installed (e.g. a venv) — otherwise tone checking
  is skipped; `--recheck-tones` re-tests existing clips. Tone demos say
  "第一声，妈。" etc. Still ask the parent to listen to changed clips. To
  change voice/params, bump the dir name (`girl-v1` → `girl-v2`) so the
  immutable cache doesn't serve old files; set `VOICE` in both places.
  Boy voices tried and available for later: `clever_boy`, `cute_boy`.
- Gamification: XP, combo streak, daily goal (3 lessons), day streak, confetti.
- Settings on home screen: 模式 (看图+读字 default / 挑战不提示), 语速 (很慢 .45 default /
  慢 .6 / 正常 .8), 🔧 声音检测 diagnostics panel.

## Important lessons learned (don't regress these)
1. **The child can't read many characters yet.** That's why hint mode exists:
   picture + auto-read for every prompt. Don't add questions that require
   reading unfamiliar characters in hint mode.
2. **Speech must start synchronously inside a tap handler** (iOS requirement).
   No `setTimeout` before `speechSynthesis.speak()`. The 3 parts of a reading
   (字 / 词 / 词的字) are queued at once.
3. **Only call `speechSynthesis.cancel()` when `speaking || pending`.** On iOS,
   cancel-then-speak when idle silences the next utterance.
4. Always stop speech on next question / quit / result, or old readings keep
   playing over the new question.
5. **iPhone silent switch mutes Web Speech** even though music apps play
   (now solved by the pre-recorded `<audio>` clips; the notes below apply only
   to the Web Speech fallback).
   `navigator.audioSession.type='playback'` + a looping silent `<audio>` were
   added (helps Web Audio beeps) but speech is still muted in silent mode —
   user accepted this. A yellow tip (`MUTE_TIP`) tells iOS users to flip the
   switch. The real fix, if ever wanted: pre-recorded audio files played via
   `<audio>` (e.g. generated with macOS `say -v Tingting` or edge-tts on the
   user's machine; the cloud sandbox couldn't reach TTS services).
6. `confirm()`/`alert()` are avoided (blocked in some embedded viewers); quit
   confirmation is an in-page sheet (`askQuit`).
7. In the WeChat in-app browser speech usually doesn't work — diagnostics panel
   tells the user to open in Safari.

## Testing
No test suite. After edits: extract the `<script>` and run `node --check`, and
for logic changes run `makeQ()` over all items in both `hintMode` values with a
stubbed DOM/localStorage to confirm every question gets 4 distinct options.
For audio changes, serve the repo with `python3 -m http.server` and drive it
with Playwright, logging `HTMLMediaElement.play` srcs/rates and stubbing
`speechSynthesis.speak` to confirm no fallback happens.
